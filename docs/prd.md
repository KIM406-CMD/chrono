# 网上超市系统 - 产品需求文档（PRD）

---

## 一、项目概述

| 项目 | 说明 |
|------|------|
| **项目名称** | 网上超市系统 |
| **项目类型** | 课程设计 |
| **项目描述** | 用户通过浏览器访问网上超市系统，以分类形式浏览商品，支持关键词检索，将商品加入购物车并模拟支付完成下单。后台提供商家入驻、商品管理、订单管理及销售报表功能。 |

### 技术栈

| 层级 | 技术选型 |
|------|----------|
| 后端框架 | Java + Spring Boot |
| 前端框架 | Vue |
| 数据库 | MySQL |
| 缓存 | Redis |
| 搜索引擎 | Elasticsearch |
| 接口文档 | Knife4j（Swagger） |

---

## 二、用户角色与权限

| 角色 | 权限描述 |
|------|----------|
| **游客** | 仅可浏览商品、查看商品详情和分类，**不能**加入购物车和购买 |
| **注册用户** | 登录后可浏览商品、搜索商品、加入购物车、下单、支付、确认收货、申请退款/退货 |
| **商家** | 注册后需管理员审核通过方可入驻；可管理自己的商品（含库存）、查看自己商品的销售情况 |
| **管理员** | 最高权限：管理用户、审核商家入驻、管理所有商品和分类、管理订单（含退款/退货审核）、查看全局销售报表 |

## 三、功能模块详述

### 3.1 用户模块

- **注册**：用户名、密码、手机号、邮箱，选择角色（普通用户/商家），需填写图形验证码
- **登录/登出**：Session 或 JWT Token 认证，Redis 缓存登录态，登录时需输入图形验证码
- **忘记密码**：通过手机号/邮箱获取验证码，验证通过后重置密码
- **个人信息管理**：修改密码、绑定手机/邮箱
- **收货地址管理**：支持多个收货地址，可设为默认地址

### 3.2 商品模块

#### 3.2.1 分类体系

- 支持**三级分类**，示例：`电子产品（一级） → 手机通讯（二级） → 智能手机（三级）`
- 后台可**动态管理**（增、删、改、查分类）
- 数据库采用 `parent_id` 自关联实现树形结构

#### 3.2.2 商品属性

| 字段 | 说明 |
|------|------|
| 商品名称 | 必填 |
| 商品描述 | 富文本 |
| 商品图片 | 支持多张 |
| 价格 | 以分为单位存储，避免浮点精度问题 |
| 库存 | 整数 |
| 品牌 | 选填 |
| 所属分类 | 关联三级分类 |
| 所属商家 | 关联商家用户 |
| 状态 | 上架/下架 |
| 销量 | 累计销量 |
| 上架时间 | 时间戳 |

#### 3.2.3 商品浏览

- 按分类层级逐级浏览
- 商品列表支持分页
- 点击商品进入详情页，展示完整信息

### 3.3 搜索模块（Elasticsearch）

| 功能 | 说明 |
|------|------|
| **全文检索** | 基于 Elasticsearch 对商品名称、描述、品牌进行全文搜索 |
| **搜索建议/自动补全** | 用户输入关键词时实时提示相关搜索词 |
| **多条件筛选** | 按价格区间、品牌、分类进行筛选 |
| **排序** | 按销量、价格（升/降）、上架时间排序 |
| **搜索历史** | 记录登录用户的搜索历史，支持清除 |

> 商品数据变更（新增/修改/下架）时，通过异步方式同步到 Elasticsearch 索引。

### 3.4 购物车模块

| 规则 | 说明 |
|------|------|
| 存储方式 | **数据库存储**（服务端） |
| 使用条件 | **仅登录用户**可使用，游客不可用 |
| 功能 | 添加商品、修改数量、删除商品、选中/取消选中 |
| 库存校验 | 加入购物车时校验库存，超库存提示用户；结算时再次校验 |

### 3.5 订单模块

#### 3.5.1 下单流程

1. 用户从购物车选中商品，点击"去结算"
2. 确认收货地址、商品清单、总金额
3. 提交订单，订单状态为「待支付」
4. 跳转支付页面

#### 3.5.2 订单状态流转

```
待支付
  ├──→ 已取消（用户主动取消 / 超时自动取消）
  │
  └──→ 已支付 ──→ 已发货 ──→ 已收货（用户手动确认收货）──→ 已完成
                    │                │
                    │                └──→ 退款/退货申请 ──→ 审核中 ──→ 退款/退货通过
                    │
                    └──→ 退款/退货申请 ──→ 审核中 ──→ 退款/退货通过
```

| 状态 | 说明 | 操作者 |
|------|------|--------|
| 待支付 | 订单已创建，等待付款 | 系统 |
| 已取消 | 待支付状态下的取消 | 用户/系统 |
| 已支付 | 支付成功，等待发货 | 用户 |
| 已发货 | 商家已发货 | 商家 |
| 已收货 | 用户手动确认收货 | 用户 |
| 已完成 | 订单完结 | 系统 |
| 退款/退货申请 | 用户发起退款或退货 | 用户 |
| 审核中 | 管理员/商家审核中 | 管理员/商家 |
| 退款/退货通过 | 审核通过，退款完成 | 管理员/商家 |

### 3.6 支付模块（模拟支付）

> 不接入真实第三方支付接口，仅做前端模拟和格式校验。

#### 3.6.1 卡号支付

- 用户输入卡号、有效期、CVV
- **Luhn 算法**校验卡号格式合法性
- 有效期格式校验（MM/YY，不能过期）
- CVV 格式校验（3 或 4 位数字）
- 校验通过后，模拟支付成功，订单状态变更为「已支付」

#### 3.6.2 二维码支付

- 系统生成模拟支付二维码（包含订单信息）
- 用户确认支付后，模拟支付成功
- 订单状态变更为「已支付」

### 3.7 商家端

#### 3.7.1 入驻流程

1. 用户注册时选择"商家"角色
2. 提交商家入驻申请（店铺名称、联系方式等）
3. 管理员审核
4. 审核通过后，商家可登录商家后台

#### 3.7.2 商家功能

| 功能 | 说明 |
|------|------|
| 商品管理 | 增删改查自己的商品，上架/下架 |
| 库存管理 | 修改商品库存数量 |
| 订单管理 | 查看自己商品的订单，进行发货操作 |
| 退款/退货审核 | 审核退款/退货申请 |
| 销售统计 | 查看自己商品的销售额、销量统计 |

### 3.8 管理员端

| 功能 | 说明 |
|------|------|
| 用户管理 | 查看、启用/禁用用户 |
| 商家审核 | 审核商家入驻申请 |
| 分类管理 | 三级分类的增删改查 |
| 商品管理 | 全局商品管理（可操作所有商家商品） |
| 订单管理 | 查看所有订单，处理退款/退货审核 |
| 销售报表 | 日/周/月销售额、按分类统计、热销商品排行等 |

## 四、数据与缓存概要

- **数据库（MySQL）**：存储用户、商品、分类、购物车、订单、支付记录、收货地址、评论等核心业务数据。详细表结构设计见 [db-design.md](./db-design.md)。
- **缓存（Redis）**：缓存用户登录态、热门商品、分类树、搜索热词、验证码等，降低数据库压力。详见 [db-design.md](./db-design.md)。
- **搜索引擎（Elasticsearch）**：为商品建立搜索索引，支持全文检索、搜索建议和多条件筛选。详见 [db-design.md](./db-design.md)。

## 五、非功能性需求

| 需求 | 说明 |
|------|------|
| 安全性 | 密码加密存储（BCrypt），接口鉴权，防 SQL 注入（MyBatis 参数化查询） |
| 性能 | Redis 缓存热点数据，Elasticsearch 加速搜索 |
| 可用性 | 前端响应式布局，适配 PC 端 |
| 可维护性 | 代码分层（Controller → Service → Mapper），Knife4j 自动生成接口文档 |
