# 网上超市系统 — 需求分析文档

---

## 一、引言

### 1.1 项目来源

本系统为课程设计项目，题目描述如下：

> 用户通过浏览器访问网上超市系统，系统以分类的形式显示所有商品，帮助用户逐步找到所要的商品；系统也提供关键词检索功能；用户在浏览商品目录时可以点击查看商品的具体信息和价格；如果满意，用户可以将商品暂时放入"购物车"；也可以随时从"购物车"中取出商品。当用户选完后可以进行付款处理，这时用户输入信用卡号，系统联系对应的银行支付系统，开始支付。最后系统应能够向管理员提供查询界面和各类报表，统计商品的销售情况。

基于以上文字描述进行需求扩展与细化。

### 1.2 适用范围

本文档对网上超市系统进行全面的需求分析，涵盖功能需求、非功能需求、角色分析、业务流程和数据需求，作为后续概要设计和详细设计的依据。

## 二、用户角色分析

| 角色 | 描述 | 核心权限 |
|------|------|----------|
| **游客** | 未登录的浏览者 | 浏览商品列表、按分类筛选、查看商品详情、关键词搜索 |
| **注册用户** | 已注册并登录的用户 | 游客权限 + 加入购物车、管理购物车、下单、支付、确认收货、申请退款/退货、发表评论 |
| **商家** | 审核通过的商家 | 用户权限 + 提交入驻申请、管理自己的商品（增删改查/上下架/库存）、管理订单（发货）、审核退款/退货、查看销售统计 |
| **管理员** | 系统最高权限 | 用户管理、商家入驻审核、三级分类管理、全局商品管理、全局订单管理、退款/退货审核、全局销售报表 |

### 2.1 角色继承关系

```
游客 ──(登录)──→ 注册用户 ──(入驻审核)──→ 商家
                  │
                  └──(系统设定)──→ 管理员
```

- 游客是最基础的匿名角色
- 注册用户登录后继承游客的所有权限，并扩展购物车、下单等功能
- 商家继承注册用户的所有权限，并扩展商品管理、订单管理等功能
- 管理员为独立的后台角色，不继承购物相关功能

```
待支付 ──→ 已取消（用户取消 / 超时取消）

                   │            │
                   │            └──→ 退款/退货申请 ──→ 审核中 ──→ 已通过（退款完成）
                   │
                   └──→ 退款/退货申请 ──→ 审核中 ──→ 已通过（退款完成）
```

## 四、非功能性需求

| 类别 | 需求描述 |
|------|----------|
| **性能** | 商品列表查询响应时间 < 1s；搜索响应时间 < 2s；支持 100 并发用户 |
| **安全性** | 密码 BCrypt 加密存储；JWT + Redis 双校验认证；防 SQL 注入（MyBatis 参数化）；接口权限校验 |
| **可用性** | 前端适配 PC 端浏览器（Chrome / Edge），响应式布局 |
| **可维护性** | 后端：Controller → Service → Mapper 分层；前端：组件化开发；统一异常处理 |
| **可靠性** | 下单使用分布式锁防并发；支付做幂等处理；库存扣减使用乐观锁（`WHERE stock >= ?`） |

## 五、业务流程

### 5.1 核心购物流程

```
浏览商品（分类/搜索）
    → 点击查看详情
    → 选择规格 → 加入购物车（需登录）
    → 进入购物车 → 选中商品 → 去结算
    → 确认收货地址 → 确认订单金额
    → 提交订单（防重Token + 扣库存）
    → 选择支付方式（卡号/二维码）
    → 支付成功
    → 商家发货
    → 确认收货
    → 完成
```

### 5.2 退款/退货流程

```
用户端：确认收货 → 订单详情 → 申请退款/退货（选择类型 + 填写原因）
商家/管理员端：审核申请 → 通过/拒绝
  ├── 通过：用户寄回商品 → 商家确认收到 → 退款 → 恢复库存
  └── 拒绝：填写拒绝原因 → 流程终止
```

### 5.3 商家入驻流程

```
用户注册 → 选择"商家"角色 → 填写入驻信息（店铺名/营业执照/电话）
    → 提交申请 → 管理员审核 → 通过/拒绝
    → 通过后商家可登录后台管理商品
```

### 5.4 忘记密码流程

```
用户端：点击"忘记密码" → 输入图形验证码 → 验证通过后输入手机号/邮箱
    → 获取短信/邮箱验证码 → 输入验证码 → 校验通过 → 输入新密码
    → BCrypt 加密存储 → 跳转登录页
```

### 5.5 用户注册/登录流程（验证码版）

```
用户端：进入注册/登录页 → 页面加载时请求图形验证码（UUID + 图片Base64）
    → 填写表单（含图形验证码） → 提交时校验图形验证码（一次性，校验后删除）
    → 验证通过后继续注册/登录逻辑
```

## 六、数据需求概要

| 数据实体 | 核心字段 | 说明 |
|----------|----------|------|
| 用户 (user) | 用户名、密码(BCrypt)、手机号、邮箱、角色、状态 | 支持游客/用户/商家/管理员 |
| 商家 (merchant) | 关联用户ID、店铺名、营业执照URL、审核状态 | 用户与商家一对一 |
| 分类 (category) | 名称、父级ID、层级(1/2/3)、排序 | parent_id 自关联 |
| 商品 (product) | 名称、描述、图片、品牌、分类、商家、上架状态 | 价格库存下沉到 SKU |
| 商品SKU (product_sku) | 关联商品、规格值组合、价格(分)、库存 | 支持多规格多价格 |
| 购物车 (cart_item) | 用户、SKU、数量、选中状态 | 同一SKU重复时合并 |
| 订单 (order) | 订单号、用户、地址快照、金额、状态、各时间节点 | 地址下单时快照 |
| 订单明细 (order_item) | 订单、商品、SKU、数量、单价、小计 | 单价存下单时刻值 |
| 支付记录 (payment) | 订单、支付方式、金额、状态 | 模拟支付 |
| 退款/退货 (refund) | 订单明细、申请人、类型、金额、审核状态 | 支持部分退款 |
| 评论 (comment) | 商品、用户、内容、评分、图片 | 支持追评 |
| 会话/消息 (conversation/message) | 用户、商家、消息内容 | WebSocket 通讯 |
