# 网上超市系统 - 产品需求文档（PRD）

> 本文档从产品视角描述系统的业务背景、用户角色与核心业务规则。
> 工程化的功能需求清单（编号 + 优先级）、业务流程、数据需求详见 [requirements-analysis.md](./requirements-analysis.md)。

---

## 一、项目概述

| 项目 | 说明 |
|------|------|
| **项目名称** | 网上超市系统 |
| **项目类型** | 课程设计 |
| **项目描述** | 用户通过浏览器访问网上超市系统，以分类形式浏览商品，支持关键词检索，将商品加入购物车并模拟支付完成下单。后台提供商家入驻、商品管理、订单管理及销售报表功能。 |

### 原始题目描述

> 用户通过浏览器访问网上超市系统，系统以分类的形式显示所有商品，帮助用户逐步找到所要的商品；系统也提供关键词检索功能；用户在浏览商品目录时可以点击查看商品的具体信息和价格；如果满意，用户可以将商品暂时放入"购物车"；也可以随时从"购物车"中取出商品。当用户选完后可以进行付款处理，这时用户输入信用卡号，系统联系对应的银行支付系统，开始支付。最后系统应能够向管理员提供查询界面和各类报表，统计商品的销售情况。

---

## 二、用户角色与权限

| 角色 | 权限描述 |
|------|----------|
| **游客** | 仅可浏览商品、查看商品详情和分类，**不能**加入购物车和购买 |
| **注册用户** | 登录后可浏览商品、搜索商品、加入购物车、下单、支付、确认收货、申请退款/退货 |
| **商家** | 注册后需管理员审核通过方可入驻；可管理自己的商品（含库存）、查看自己商品的销售情况 |
| **管理员** | 最高权限：管理用户、审核商家入驻、管理所有商品和分类、管理订单（含退款/退货审核）、查看全局销售报表 |

## 三、核心业务规则

### 3.1 分类体系

- 支持**三级分类**，示例：`电子产品（一级） → 手机通讯（二级） → 智能手机（三级）`
- 后台可**动态管理**（增、删、改、查分类）
- 数据库采用 `parent_id` 自关联实现树形结构

### 3.2 商品属性

| 字段 | 说明 |
|------|------|
| 商品名称 | 必填 |
| 商品描述 | 富文本 |
| 商品图片 | 支持多张 |
| 价格 | 以分为单位存储，避免浮点精度问题 |
| 库存 | 整数（下沉到 SKU 级别） |
| 品牌 | 选填 |
| 所属分类 | 关联三级分类 |
| 所属商家 | 关联商家用户 |
| 状态 | 上架/下架 |
| 销量 | 累计销量 |
| 上架时间 | 时间戳 |

### 3.3 购物车规则

| 规则 | 说明 |
|------|------|
| 存储方式 | **数据库存储**（服务端） |
| 使用条件 | **仅登录用户**可使用，游客不可用 |
| 库存校验 | 加入购物车时校验库存，超库存提示用户；结算时再次校验 |

### 3.4 订单状态流转

```
待支付
  ├──→ 已取消（用户主动取消 / 超时自动取消）
  │
  └──→ 已支付 ──→ 已发货 ──→ 已收货（用户手动确认收货）──→ 已完成
                    │                │
                    │                └──→ 退款/退货申请 ──→ 审核中 ──→ 退款/退货通过
                    │
                    └──→ 退款/退货申请 ──→ 审核中 ──→ 退款/退货通过
```

### 3.5 支付业务规则（模拟支付）

> 不接入真实第三方支付接口，仅做前端模拟和格式校验。

#### 卡号支付

- 用户输入卡号、有效期、CVV
- **Luhn 算法**校验卡号格式合法性
- 有效期格式校验（MM/YY，不能过期）
- CVV 格式校验（3 或 4 位数字）
- 校验通过后，模拟支付成功，订单状态变更为「已支付」

#### 二维码支付

- 系统生成模拟支付二维码（包含订单信息）
- 用户确认支付后，模拟支付成功
- 订单状态变更为「已支付」

### 3.7 秒杀券业务规则

> 秒杀券是一种限时限量优惠券，用户在指定时间内抢领，下单时可用券抵扣金额。

| 规则 | 说明 |
|------|------|
| 券类型 | 满减券（满X减Y）、折扣券（打Z折，如9折） |
| 发放方式 | 后台创建秒杀券活动，设定总量、每人限领数量、活动时间 |
| 领取规则 | 活动期间用户手动抢领，先到先得，每人有领取上限 |
| 使用规则 | 下单时选择一张未使用的券，满足最低消费门槛后抵扣 |
| 过期规则 | 券活动结束后，未使用的券自动过期；已使用的券不可退款 |
| 并发控制 | Redis 扣减剩余数量 + 已领取标记，保证高并发下不发超 |
| 叠加规则 | 每笔订单仅可使用一张券，不可与其他券叠加 |

### 3.8 商家入驻流程

1. 用户注册时选择"商家"角色
2. 提交商家入驻申请（店铺名称、联系方式等）
3. 管理员审核
4. 审核通过后，商家可登录商家后台

## 四、非功能性需求

| 需求 | 说明 |
|------|------|
| 安全性 | 密码加密存储（BCrypt），接口鉴权，防 SQL 注入（MyBatis 参数化查询） |
| 性能 | Redis 缓存热点数据，Elasticsearch 加速搜索 |
| 可用性 | 前端响应式布局，适配 PC 端 |
| 可维护性 | 代码分层（Controller → Service → Mapper），Knife4j 自动生成接口文档 |

> 更详细的非功能需求指标（响应时间、并发数等）见 [requirements-analysis.md](./requirements-analysis.md)。
